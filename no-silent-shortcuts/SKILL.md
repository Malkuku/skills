# No Silent Shortcuts

任何会阻止、跳过、取消、吞掉或延迟真实意图的控制流短路，都必须留下可观测的原因。

意图包括用户操作、API 请求、业务动作、后台任务、状态同步、数据写入、消息处理或调用方的明确期待。

## 规则

新增或修改 `return`、`continue`、`break`、异常处理、取消逻辑、no-op 或状态终止分支时，先判断：

- **无害短路**：纯内部 no-op，不影响调用方期待或业务结果，可以直接返回。
- **关键短路**：阻止或改变真实意图，必须在决策发生处解释原因。

关键短路应按项目惯例通过日志、明确返回值、异常、诊断事件或可检查状态等方式暴露，并提供足以判断以下事项的上下文：

- 为什么没有继续；
- 哪个状态、条件、输入或依赖不满足；
- 原本的意图是被保留、消费、取消还是忽略。

不要因为某个底层步骤成功，就直接把整体意图标记为完成；只有业务完成条件真正成立时才能消费该意图。

示例：

```ts
logger.debug("Skipping operation", {
  reason,
  operationId,
  currentState,
  consumedIntent: false
});
````

## 审查

检查 diff 中可能提前结束流程的分支，包括：

* `return` / `continue` / `break`
* 空 `catch` 或默认 no-op
* 丢弃事件、回调、请求或任务
* 清除或取消待处理意图
* 转入 `idle` / `done` / `error` / `cancelled`

如果该分支会影响真实意图，却无法从外部判断为什么发生或意图如何处理，应补充诊断。
