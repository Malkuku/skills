# 小说工作区初始化与既有小说接入

仅在以下场景读取本文档：

- 用户开始一部新小说，希望建立小说 Spec 工作区。
- 当前工作区缺少 `Spec/索引.md`、`Spec/核心创作说明.md`、`Spec/大纲/总体大纲.md` 或正文目录。
- 用户把已有大纲、设定或正文接入本工作流。
- 现有材料分散，尚未形成可维护的当前有效 Spec。

初始化完成后，回到主工作流。不要在日常创作中反复加载本文档。

## 先判断接入场景

### 新小说

作品尚未形成稳定正文或完整资料。通过讨论建立最小工作区，不要求作者一次性想清整部小说。

### 既有小说

已经存在大纲、设定、正文、角色卡、世界书或其他材料。先理解现状，再整理当前有效 Spec；不要按照模板重新发明故事。

如果资料量很大，先建立可导航的文档树和最小可用上下文，再逐步整理。不要承诺一次性反向整理全部正文和历史版本。

## 新小说初始化

### 需要形成的最小共识

初始化只处理当前无法绕开的上层内容：

- 作者希望读者获得的主要体验。
- 作品整体基调。
- 明确的创作边界。
- 当前已经构思出的故事主脉络，以及仍是候选的部分。

优先使用 `grill-me` 讨论真正会改变作品方向的决定。不要把人物模板、世界观清单、章节数量、叙事术语等操作细节一次性抛给作者。

### 最小初始化产物

```text
小说工作区/
├─ Spec/
│  ├─ 索引.md
│  ├─ 核心创作说明.md
│  ├─ 设定/
│  └─ 大纲/
│     └─ 总体大纲.md
└─ 正文/
```

`GRILL_ME_DISCUSSION.md` 只在讨论预计跨多轮时临时创建。

不要因为目录已经存在就生成空的人物、关系、世界、时间线、章节或任务文档。设定文档只在已有内容需要明确归属时创建。

### 核心创作说明

只写已经确认的作者约束：

```md
# 核心创作说明

## 期望体验
- ...

## 整体基调
- ...

## 创作边界
- ...
```

不把故事前提、人物处境、世界观、主线或结局写入该文件。

### 总体大纲

总体大纲保存当前故事构想和具体剧情规划，可以只覆盖作者目前构思到的范围。

允许在同一文件中使用最小标记区分：

```md
## 已确认

- ...

## 候选

- ...
```

也可以在具体段落前标记 `[已确认]` 或 `[候选]`。不要求使用固定表格，不要求预先拆分卷、篇章、节点、章节和场景。

如果内容尚未明确，可以保留空缺或候选，不由 AI 擅自补成正式剧情。

### 索引

初始化后的 `Spec/索引.md` 只包含极简进度和真实文档树：

```md
# Spec 索引

## 当前进度

- 当前大纲：`大纲/总体大纲.md`
- 当前正文：尚未开始
- 当前状态：大纲构思
- 当前独立任务：无

## Spec 文档树

- [核心创作说明](./核心创作说明.md)：作者期望体验、整体基调与创作边界。
- [总体大纲](./大纲/总体大纲.md)：当前故事构想、具体剧情规划及候选内容。
```

只登记真实存在的正式 Spec。`设定/` 尚无文档时，不必在文档树中展开空分支。

## 既有小说接入

### 读取顺序

根据现有材料选择最短路径：

1. 读取已有目录、索引、说明和作者明确标注的当前版本。
2. 读取现有大纲与设定，识别用户已经明确确认的内容。
3. 按需要读取已确认正文，确认实际写成的事件和当前有效变化。
4. 只有现有材料无法确定、且会影响整理结果时，才向用户询问。

不要求机械全文阅读所有正文。优先从已有导航、章节范围和明确关联定位必要内容；资料冲突或当前版本不明时，再扩大读取范围。

### 整理原则

- 用户明确说明的当前版本优先作为整理依据。
- 已确认正文证明故事实际写出了什么。
- 现有设定和大纲分别承担当前有效事实与未来剧情规划。
- 从正文反向整理出的内容必须标明是明确事实还是根据文本推断。
- 不能可靠判断的内容保留为待确认，不擅自修正、调和或补完。
- 不把旧版、废案、聊天记录和历史草稿混入当前有效 Spec。

### 接入步骤

1. 盘点现有正式材料、正文版本和明显历史文件。
2. 创建或补全 `Spec/索引.md`，登记真实存在或本次整理出的正式 Spec。
3. 从作者已有说明中整理 `核心创作说明.md`；缺少时只讨论体验、基调与边界。
4. 将当前故事构想整理到 `大纲/总体大纲.md` 或已有大纲结构中，保留候选/已确认区别。
5. 将当前有效人物、关系、世界及其他设定归入 `Spec/设定/` 下合适位置；不强制统一目录模板。
6. 把正文保留在 `正文/` 或用户已有正文位置，不复制进 Spec。
7. 更新索引中的当前进度指针和文档树。
8. 将仍需高影响决策的问题交给 `grill-me`；稳定结论迁移完成后清理讨论草稿。

接入工作的目标是建立可继续创作的当前上下文，不是重写已有小说、补齐全部设定或统一所有历史文本。

## 历史与迁移

正式 Spec 只保留当前有效版本，普通历史交由 Git 或用户已有版本管理承担。

如果新旧设定仍同时影响当前正文或大纲，可以暂时保留迁移说明：

```md
## 临时迁移说明

- 已废弃内容：...
- 尚受影响的大纲或正文：...
- 需要完成的调整：...
- 清理条件：...
```

迁移完成后删除本节。不要把迁移说明演变成永久变更日志。

## 初始化边界

- 不创建当前故事快照或独立时间线库。
- 不强制规定 `设定/` 的人物、关系、世界等子目录。
- 不强制大纲采用固定层级、字段或生命周期。
- 不为了完整性编造人物动机、世界规则和未来剧情。
- 不把候选方案写成当前有效设定或已确认剧情。
- 不一次询问大量可以在第一部小说实践中逐步调整的流程细节。
- 不把工作区初始化扩大为全文润色、剧情重写或完整创作教学。

## 初始化完成判定

满足以下条件后，结束 onboarding 并回到主工作流：

- `Spec/索引.md` 能定位当前存在的正式 Spec，并记录极简进度。
- `核心创作说明.md` 已保存当前能够确认的体验、基调和边界。
- 总体大纲已保存当前已有故事构想，并区分候选与已确认内容。
- 已有设定有明确归属；尚未需要的设定文档没有被机械创建。
- 正文位置和当前有效版本已经明确。
- 剩余高影响问题已有讨论入口，不需要 AI 擅自补齐。
