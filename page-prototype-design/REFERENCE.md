# Page Prototype Reference Notes

## 参考前先定义目标

参考页面不是复制风格。先写清楚：

- 要解决的信息架构问题。
- 要观察的交互模式。
- 当前页面不能照搬的业务差异。
- 需要避免的噪音，例如营销文案、无关插图或炫技动画。

## 观察维度

参考工作台、控制台或任务页面时，重点看：

- 首屏最先让用户判断什么。
- 时间范围、筛选条件和状态是否清楚。
- 核心动作是否靠近对应对象。
- 重要内容是否通过空间结构表达，而不是只靠颜色。
- 解释性内容是否真的帮助用户行动。
- 空态、失败态、加载态是否与主流程一致。

## 归纳方式

把参考结果拆成三类：

- 可采用：适合当前业务和用户动作的结构。
- 可改造：方向有价值，但需换成项目内语言或交互。
- 不采用：与当前页面目标冲突，或只是视觉装饰。

## 输出模板

```md
目标页面：
主问题：

可采用：
- ...

可改造：
- ...

不采用：
- ...

落地约束：
- ...
```

## 常见反例

- 用规则说明替代清晰布局。
- 把 AI 摘要放进任务执行区，但没有任何直接动作。
- 把静态范围做成按钮，导致用户误以为可以切换。
- 为了显得丰富塞入过多字段，任务清单反而不能快速完成或取消。
- 时间轴表达的是截止时间，却设计成生活时间段或日程排程。
