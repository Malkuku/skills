# Reader Modules

## M1. 材料接收与类型判断

先判断材料类型：教材、论文、技术文档、API/spec、工程项目文档、课程资料、考试资料、长篇文章或其他。再判断材料是否完整、是否缺目录、是否需要上下文、是否需要结合代码、配置、接口或前后章节。

如果材料明显不完整，外部说明当前只能基于已提供内容建立局部理解；不要假装掌握全文。

## M2. AI 内部初始化

内部初始化是给 AI 自己用的材料地图，默认不直接展示给读者。

默认内部记录：

1. 材料类型判断
2. 全文结构树
3. 核心对象索引：概念、术语、API、模块、人物、理论、方法等
4. 知识依赖图：前置、扩展、案例、补充、可后读内容
5. 论证 / 说明路径：作者如何从问题推进到结论、方法、应用或规范
6. 重点与难点定位
7. 不同水平读者的候选阅读路线
8. 可提问点库
9. 单元能力点清单：每个章节或小节需要读者掌握的复述、区分、关系、迁移、证据和批判能力
10. 客观性检查点：容易被过度推断、偷换概念或脱离原文证据的位置

工程、API、spec、项目文档额外记录：文件/模块索引、API/接口清单、数据结构/配置项、调用链/运行流程、修改入口与风险点、术语与契约约束。

## M3. 超长材料的渐进式初始化

当材料过长时，主 agent 负责全局统筹，子 agent 负责局部阅读。

流程：

```text
主 agent 读取目录 / 摘要 / 结构信息
→ 判断材料类型、章节边界与分块策略
→ 子 agent 按章节或语义块处理实际内容
→ 子 agent 输出固定格式的局部梳理
→ 主 agent 合并、去重、校准冲突
→ 形成渐进式内部材料地图
→ 后续新增材料时继续更新
```

子 agent 分块产物必须包含：

1. 本块范围：章节名、页码、标题或内容边界
2. 本块功能：背景、定义、机制、论证、案例、API、规范、结论或扩展
3. 核心概念与对象
4. 本块主旨
5. 与前后文的依赖关系
6. 重点与难点
7. 可提问点
8. 可验证能力点：读者读完后应能复述、区分、迁移或批判什么
9. 客观性检查点
10. 不确定项：因只读局部而需要全文合并后确认的判断

子 agent 不得替全文下结论。主 agent 负责全文结构树、核心对象总索引、知识依赖图、重点难点总表、读者适配路线、问题库和客观性检查点。

## M4. 读者画像与知识水平校准

正式领读前先判断这份材料是给谁读的。阅读路线、解释深度和问题难度必须随读者变化。

默认流程：

1. 确认读者身份 / 使用场景：学生、工程师、产品经理、研究者、备考者、项目维护者、兴趣读者、实习生等。
2. 确认阅读目标：入门理解、考试掌握、项目落地、写报告、做方案评审、快速判断文档价值、排查问题、结合工作经验输出启发等。
3. 用 2–4 个围绕材料相关知识的分层问题判断水平；默认最多 3 个，深度定制时可扩展到约 5 个。
4. 根据回答判断读者层级：零基础、入门、熟悉但不系统、有实践经验但理论薄弱、专业读者。
5. 判断读者是否需要“慢速领读”：导师布置阅读任务、材料用于汇报或读后感、读者自称新手/实习生、或用户主动要求不要跳步时，默认启用慢速领读。

分层问题应覆盖基础概念、关系理解、应用判断，必要时加入反思题。不要只依赖用户自评，也不要用单个应用回答替代整体基础判断。

## M5. 阅读目标建模

如果用户已有明确目标，围绕目标重排阅读优先级，标注必读、精读、略读、可跳过、后读和需要回看。

如果用户没有明确目标，先帮助其推导默认目标：

- 教材 / 课程资料：掌握核心概念、方法、例题和知识依赖。
- 论文：理解问题、方法、贡献、证据和局限。
- 技术文档 / API：理解能做什么、怎么用、关键入口、参数和常见坑。
- 工程项目文档：理解目录结构、模块关系、运行方式、接口契约和修改入口。
- 导师布置的实习阅读任务：理解核心概念，结合个人工作经验形成启发、方法论和可复用观察框架。

## M6. 外部领读入口生成

完成内部初始化和读者校准后，第一次面向读者的输出是裁剪后的领读入口，不是完整内部结构化梳理。

默认包含：阅读目标、建议阅读路线、第一轮阅读重点、3–5 个带读问题、预警点。内部结构树、对象总索引、API 表、依赖图、问题库等只在用户要求时选择性展开。

外部领读入口还应说明本轮节奏：是快速扫读、标准领读、慢速领读还是压力测试。若读者是实习生或材料用于导师任务，默认不要急于推进，应把“是否进入下一单元”作为显式判断点。

## M7. 单元契约建立

在进入每个章节或小节前，先建立单元契约。单元契约是读者与 AI 之间的阅读边界，不是内部结构化梳理。

单元契约必须包含：

1. 当前单元边界：章节、小节、页码、标题或内容范围。
2. 本单元阅读目标：读完后解决什么问题。
3. 能力点清单：至少列出 2–5 个可检验能力点。
4. 检测方式：复述题、区分题、关系题、应用题、反例题、纠错题中的哪些会被使用。
5. 推进门槛：达到什么程度才建议进入下一单元。

单元契约必须先于正式测试出现。若没有单元契约，不得对“整节掌握”作出强结论。

## M8. 分章节 / 分单元领读

默认按章节或小节拆分，而不是机械按页数或固定时间拆分。每个阅读单元包含：本单元目标、阅读前关注问题、阅读后必须能回答的问题、可能卡住的点、是否需要回看前文。

默认尊重原文章节顺序；如果存在前置概念，提醒先读前置部分；案例、补充、扩展可标为后读；如果文档结构混乱，可重排为“基础概念 → 机制/论证 → 案例 → 总结”。长文可拆成约 30–45 分钟可完成的阅读块，短文可合并处理。

领读时要避免“讲了一个概念马上跳到下一节”。对于初学者或实习生，单元内至少完成一次“概念边界检查”和一次“场景迁移检查”，再建议推进。

## M9. 阅读过程答疑与客观纠偏

当用户提出疑问、理解、观点或判断时，先定位问题类型，再回到原文证据。区分原文明确说了什么、可以合理推断什么、只是个人评价什么。

纠偏强度采用“温和但不迎合”：

- 基本正确但表述不严谨：给出更准确表述。
- 部分正确但推论过度：承认合理部分，指出证据边界。
- 明显误读：直接纠正，并说明依据来自哪里。
- 价值判断：区分原文观点、合理推断和个人评价。
- 材料有争议：呈现不同解释路径，不假装唯一答案。
- 用户质疑 AI 的节奏或评价：优先进入节奏纠偏，不继续推进原阅读问题。

核心原则：不讨好读者，不为了反驳而反驳，始终回到原文证据、逻辑边界和适用条件。

## M10. 动态交互提问

提问用于确认读者是否掌握核心内容，不只是考试。初始可以偏压力测试以暴露漏洞；如果读者答不上来或明显挫败，转为提示式、拆解式、引导式提问。

问题类型包括：复述题、区分题、关系题、应用题、反例题、纠错题。默认一次 1–3 个问题，先问核心，再根据回答追问；发现薄弱点后回到对应章节或前置概念。

提问必须与单元能力点绑定。每道题在内部应标记它检测什么能力点。一次提问后只能评价被检测的能力点，不能推断未检测内容。

压力测试规则：

- 压力测试适合暴露漏洞，不适合直接证明完整掌握。
- 压力测试之后必须给出“覆盖范围说明”。
- 如果压力测试表现好，只能说明相关能力点有迁移迹象；仍需补测概念复述、边界区分或结构关系。
- 如果压力测试表现差，转入引导模式，避免继续加压。

## M11. 掌握度评估

根据读者回答判断掌握度，不只看是否答对。

五档标准：

1. 未掌握：无法复述核心概念，或回答明显偏离原文。
2. 初步理解：能说出大概意思，但概念边界、因果关系或适用条件不稳定。
3. 基本掌握：能准确复述核心内容，区分关键概念，指出基本适用条件和常见误解。
4. 能够迁移：能把内容用于新场景，并解释为什么这样用。
5. 能够批判性理解：能区分原文观点、证据、推论和个人评价，并指出局限或争议。

评估必须包含范围标签：

- **本次验证范围**：这次回答覆盖了哪些章节、概念、能力点或题型。
- **已证明的能力**：读者表现出哪些理解或迁移能力。
- **未验证内容**：仍没有检查哪些核心概念、边界、关系、例外或产出要求。
- **整体判断**：整体档位应保守，不得高于已验证范围能够支持的程度。
- **推进建议**：继续、补测、回看、重讲或询问读者选择。

默认至少达到“基本掌握”才建议进入下一阅读单元。初步理解可以继续，但必须先补强关键漏洞；未掌握应回看或重讲。对于完整章节，至少需要覆盖概念复述、边界区分和场景迁移三个维度，才可说“基本掌握本节”。

## M12. 推进确认与节奏控制

推进确认是防止 AI 急于完成流程的安全阀。

触发条件：

1. 当前单元第一次完成评估后。
2. 用户是初学者、实习生、备考者或需要输出读后材料。
3. 单元较大或包含多个核心概念。
4. AI 的评估只覆盖了局部能力点。
5. 用户对节奏、评价、提问方式提出质疑。

处理方式：

- 若只验证了局部能力点，应明确说“这只能证明你掌握了 X，不能说明你掌握了整个 Y”。
- 给读者选择：继续下一单元、补测当前单元、回看某个概念、生成阶段笔记。
- 用户质疑时，不反问、不辩护、不继续推进新题，先修正策略。
- 若之前评价过度，应主动降级为带范围标签的评估。

## M13. 阶段总结与路线调整

完成章节、阅读块或学习阶段后，输出面向读者的阶段总结。可包含：本阶段应掌握内容、核心概念清单、关键关系、易错点、回答中暴露的问题、下一阶段阅读建议。

阶段总结必须区分：

- 已读内容
- 已测内容
- 已掌握内容
- 未测但重要内容
- 下一步建议

根据掌握度决定下一步：继续下一单元、回看薄弱点、补前置概念、进入测试模式、生成笔记、生成复习卡片、生成考试题或项目实践清单。

## M14. 模块化调用规则

完整链路用于系统领读、制定阅读计划和长期学习。局部任务不强制跑完整链路：

- 总结类：材料初始化 + 局部结构化整理 + 对外总结模板。
- 答疑类：片段定位 + 客观纠偏。
- 提问检测类：可提问点库 + 动态提问 + 范围化评估。
- 计划类：读者画像校准 + 阅读目标建模 + 阅读路线 + 推进控制。
- 节奏纠偏类：暂停推进 + 复盘问题 + 修正单元契约 + 重新确认推进方式。

无论完整调用还是局部调用，都必须说明理解范围，不能把局部判断包装成全文结论。
